30 秒看懂

Battery Evidence Lab 是一个本地证据检索页面：它可以按关键词查论文、读取知识库中的论文记录、在本机已下载的 PDF 中找带页码的短摘录，并生成方法工作流。工具 Agent 只在这些白名单工具中选择，不能运行 Python/系统命令、修改 Zotero、下载任意网址、提交 VASP 作业或推送 Git。

你会遇到三种模式：

模式能做什么模型是否参与适合什么时候
静态 GitHub Pages阅读公开元数据、教程和已构建页面不能运行本项目 Python，也不保存密钥只想浏览或分享
本机确定性流程本地检索、全文页码摘录、方法工作流未配置模型；下一步由固定流程执行不出机、先验收检索
本机模型 Agent在本地证据包上选择下一工具并组织带引用回答需要兼容的 chat-completions 服务；最多 4 次工具调用需要追问和组合证据

没有配置模型时，动作记录会标明确定性流程（接口中的模式名为 deterministic_workflow）；这不是“生成式 Agent 已接通”。联网模型的实际效果也必须单独验收。

从 start.bat 到第一个问题

  1. 在项目根目录双击 start.bat，或在命令提示符运行 start.bat。它会启动本机服务并打开 http://127.0.0.1:8765；保持窗口打开，按 Ctrl+C 停止。若已有其他服务占用端口，以窗口输出为准。
  2. 先在页面确认论文数量、全文索引数量和模型状态。只浏览公开网页时，直接访问 GitHub Pages 首页，不需要运行任何脚本。需要把本机服务临时授权给远程访客时才运行 start.bat share；它会启动本机 Python 服务并建立 Cloudflare 隧道，访客只能使用受限的远程接口。
  3. 不配置模型时，直接选择工具流程，输入例如：找聚合物电解质 MD 的可复现工作，并列出仍缺少的参数。这会执行本地的 search_papers、search_fulltext、build_workflow，结果应标明确定性模式。
  4. 要接入模型，在项目根目录运行 start.bat rag。按提示填写完整的 http(s) chat-completions 地址、模型名称和密钥；本地模型没有密钥时直接回车。配置只存在于本次进程环境中，不写入仓库或页面。
  5. 这里有两个不同的“远程”：如果本机用户配置远程模型 endpoint，模型会收到本次问题以及被选中的论文元数据/全文短摘录，不会收到整个本地 PDF；因此仍要先确认供应商政策，未公开课题、企业配方和私人笔记不要上传。若是远程访客通过共享 HTTP 地址访问本机服务，服务端不会启用本地全文 RAG，/api/agent 也会拒绝远程请求；访客不能因此获得工具 Agent 或本地 PDF。若要求证据不出机，使用本地模型或不配置模型。
  6. 回到页面选择工具 Agent，重新提问同一问题，再检查动作记录和最终引用。第一个通过样例不是“答案听起来合理”，而是能看见相关工具动作、实际证据和可追溯来源。

工具白名单：真实名称、输入和输出

/api/agent 只接受本机回环请求；问题必须是 1–4000 个字符。工具循环最多 4 次调用，结果会被截断到受限大小。以下是 battery_lab/tool_agent.py 当前实现的接口摘要：

工具输入输出重点
search_papersquery：非空字符串（最多 4000 字符）；limit：整数 1–5query 和 papers[]；每条包含 id/title/authors/year/journal/doi 及已整理的摘要、方法、体系、证据、范围说明。不会返回本机路径或 Zotero key。
get_paperpaper_id：知识库中的非空字符串paper 单条安全论文记录；不存在的 id 报错。
search_fulltextquery：非空字符串（最多 4000 字符）；limit：整数 1–4hits[]，每条可含 paper_id/page/section/score/excerpt；另有 provenance，说明这是本机 PDF 的页面摘录。
build_workflowquestion：非空字符串（最多 4000 字符）方法工作流建议；它是规划材料，不等于计算已经执行。

工具结果里的论文编号（如 [P1]）只表示本次证据包中的来源。模型回答必须在正文中使用这些编号，并在末尾列出所引用的论文，有 DOI 时附上链接；有 DOI 不代表该论文已经验证了你的具体体系。search_fulltext 返回的页码只对应本机索引中的 PDF 版本，PDF 版本变化时要重新核对。

怎样核验一条回答

按“问题 → 动作 → 证据 → 原文”四步检查：

  1. 看动作记录：检索问题是否与主题相符；需要全文时是否真的调用了 search_fulltext；是否重复搜索或在没有结果时直接下结论。
  2. 看证据类型：结构化元数据只能支持题名、作者、年份、DOI 等记录；方法参数和数值主张应有全文摘录或原 PDF 支持。build_workflow 只能支持计划建议。
  3. 回到页码：打开本机原 PDF，按 paper_id 和 page 定位，核对摘录前后语境、表格/图注、单位和版本。记录“主张—页码—原句/图表”三列；页码为空时不要声称已读全文。
  4. 检查边界：把论文事实、教学解释、你的研究设想和未知项分开。若回答引用了证据包之外的编号、无来源的精确参数，或把未运行的工作写成结果，应判为不通过。

本机与远程的区别

本机回环访问可使用本机论文元数据、页码摘录和 /local-pdf/... 页面；/api/agent 只允许本机。通过 start.bat share 建立的隧道或其他公开地址访问时，服务会禁用普通聊天的本地全文 RAG，并拒绝工具 Agent；公开访客不会获得本地 PDF。GitHub Pages 是静态发布物，不能代替本机服务，也不能安全地放 API key。不要把私人 PDF、密钥、完整本地路径或 Zotero 链接提交到公开仓库。

常见故障

现象先检查
页面打不开start.bat 窗口是否仍在运行；实际端口是否为 8765；是否被另一服务占用。
模型状态未配置重新运行 start.bat rag，确认地址是完整的 /chat/completions 地址、模型名非空；本地服务无需密钥。
工具 Agent 被拒绝确认浏览器地址是同一服务的 127.0.0.1/localhost，不要用公开隧道调用 /api/agent。
全文没有命中本机是否有对应 PDF 和全文索引；先用 DOI 或题名检索，再回到原 PDF 核对版本。没有命中不能推断“论文没有该内容”。
回答没有引用或安全回退查看动作记录；模型输出不符合 JSON、引用编号无效或数值主张缺证据时，系统会回退。先缩小问题并用确定性流程复测。
密钥出现在截图/仓库立即停止分享，撤销或轮换密钥；不要把它写入 .md、HTML、日志或提交历史。

后续评估顺序

先收集一组彼此独立的真实问题，分别标记应找到的证据和必须拒答的情况；开发题与最终测试题分开。再比较检索召回、工具选择、引用准确性、缺证据时的拒答和成本/超时。最后才考虑微调：只有经过研究者审核的“问题—动作—证据—答案”记录才可进入训练或评估，自动生成的错误答案不能循环自训。

验收至少包括：找到正确 DOI；只引用实际返回的证据；明确元数据与全文区别；拒绝未知工具和越权路径；保留动作、版本和来源记录而不是思维链；模型失败时明确回退。Agent 只能帮助查证和组织流程，不能替代 DFT/MD 计算、原始 PDF 阅读或导师对创新性的判断。
